# Geometry reader — Codex

A laptop-local geometry editor, Adam recorder, and replay viewer. This is the independent Codex version. It uses NumPy, SciPy, a small local Python server, and browser canvas; it does not require Dash, Torch, a remote compute host, or a JavaScript build.

## Open

On Sam’s laptop, open `results/checkpoint_G_interactive/geometry_reader_codex/Geometry Reader Codex.app`, or double-click this directory’s `launch.command`. The launcher uses `~/venv/precisionMLPs/bin/python`, starts the local server, and opens **http://127.0.0.1:8068**. `GEOMETRY_READER_PYTHON` can select another interpreter with NumPy and SciPy.

For a terminal launch from the repository:

```sh
~/venv/precisionMLPs/bin/python experiments/expG02_geometry_reader_codex/run.py
```

The native launcher is generated by `make_launcher.py`; it runs computation on the machine where it is opened.

## Controls

- The large geometry plot shows **γ = |hidden weight|**. Drag amber points vertically, teal rail handles horizontally, and the pink mean-γ handle vertically. The dotted green reference is **γ ideal = λ clean / h**. Signed hidden weights are preserved internally.
- Scroll any plot to zoom the shared x axis. Shift-scroll pans x; Alt-scroll zooms that plot’s y axis. Drag empty space to pan, double-click to fit all centers, or use **Fit [−1, 1]** to inspect the data domain. All four plots share horizontal limits and pixel alignment. Selecting a neuron by number makes its handle accessible when several centers coincide exactly.
- **Interior centers · N** counts the points inside the reference domain, including its two endpoints; halo points are added separately. Auto halo uses `R=max(10,ceil(sqrt(N)))` whole points per side, `h=2/(N-1)`, and total count `W=N+2R`. The default is N=64, R=10, W=84. For N=100, R=10, W=120 and λ=0.25 gives γ=12.375. Node-count changes retain the displacement/lambda profiles and their arithmetic mean λ; γ scales inversely with the new h. A single center drag leaves γ unchanged. Explicit extents, spacing, and historic presets use custom geometry; their existing grid is retained until Auto halo is enabled. Resizing custom geometry keeps its halo count and uses the selected interior count.
- **Clean** interpolates rank-matched centers toward the configured uniform extent and λ toward the repository rule. The percentage controls interpolation strength. **Keep mean λ** retains the previous mean instead. Jitter buttons perturb centers or γ using the saved random generator.
- Readout points drag vertically. Dragging the displayed least-squares readout copies that vector into the editable Adam channel, then switches the view to Adam so the changed value remains visible. Output bias is editable too. Merely switching the view never injects parameters.

## Preview, inject, train

**Full reset**, at the top of the app, stops training or replay and restores the default target, data, geometry, readout, optimizer, recording settings, and plot controls. It clears pending previews and the current timeline. Saved runs remain available in the library. **New recording** keeps the current experiment and starts a separate recording.

While idle, paused, or replaying, geometry/readout edits are previews. **Inject geometry** and **Inject displayed readout** commit the chosen component; the latter can explicitly inject the least-squares solution. Unrelated target/data/learning-rate changes preserve pending edits. **Play** with a pending preview opens an inject/discard/cancel choice.

Direct plot edits during live training are immediate interventions: the current state is evaluated, the edit is applied, least squares is solved again, and the intervention is saved before training continues. Manual interventions reset Adam moments. Model/data/training settings stop training; replay geometry edits end replay and injection creates a new branch, preserving the source recording. Display-only controls and zoom do not change the experiment.

Adam minimizes mean squared error in the original hidden-weight/hidden-bias and readout coordinates. Readout initialization is zero or Xavier. **Least squares is a comparison by default.** The optional per-snapshot injection checkbox implements interleaved least-squares feedback. Each snapshot retains the Adam readout *before* feedback, the solved readout, both predictions and residuals, and the exact optimizer state to continue *after* feedback. A manually edited readout is protected until a gradient step consumes it.

**Steps to run** starts a block of that many steps. Pause/resume continues the current block; after it finishes, Play starts another block. Every scheduled snapshot completes the solve, both evaluations, and disk persistence before the next gradient step. Fixed and geometric spacing include the exact final step; geometric spacing multiplies each successive gap. The delay is after a snapshot, not after every gradient step.

## Recordings and replay

Recordings live in this repository’s gitignored directory:

```
results/checkpoint_G_interactive/geometry_reader_codex/runs/<run-id>/
```

Each run has a name, manifest, lightweight timeline, and individually compressed complete frames. Frames include parameters, both readouts, data/settings, predictions/residuals, Adam moments, random-generator state, and intervention metadata. Writes are atomic per frame, and the manifest advances only after the frame and timeline entry are persisted. The app reads individual frames on demand instead of loading every dense curve into memory.

Use the timeline in either direction, Previous/Next, or **Play replay**. Playback from the end starts at the first frame. Manual interventions flash the plots and affected handles and hold for about a second. Saved curves are displayed exactly as recorded; replay does not silently re-solve them. Play Adam from a replay branches from that frame’s saved optimizer state.

Long runs can remain detailed without saving every step: for example, 50,000 steps with first gap 1 and multiplier 1.3 produce 38 snapshots. Choose fixed spacing when every specific iteration matters. Browser refreshes do not interrupt the local server; stopping the server preserves completed frames, and saved runs can be loaded and resumed after reopening.

## Presets and numerical conventions

Six numerical presets are bundled in `presets/catalog.json`: clean QI, the original Xavier seed, learned Xavier-to-sine-floor geometry, scaled Xavier, soft-neuron-protected geometry, and regular clusters. Apply geometry alone or also restore the original target/data settings. The fresh Xavier button samples another initialization using the engine’s reproducible random stream.

The requested sine-floor checkpoint reached relative L2 about `6.65e-15` using **200 VarPro Adam steps followed by Gauss–Newton**. It is a saved geometry, not an invented Adam replay. Provenance, source hashes, and reproducible refit checks are in `docs/geometry_reader_codex_presets.md`. Last digits depend on the numerical libraries and machine.

The clean preset uses N=144 interior points, R=12, W=168. Historical presets and recordings retain their original halo and parameters. Historical source files use N for the number of intervals, so their `h=2/N` and width `N+2*halo+1` correspond to N+1 interior points in this app. Imported presets and old recordings preserve their reference spacing and exact arrays; their displayed interior count is translated from that historical convention. This app uses the positive magnitude γ on the vertical axis and λ=γh for the clean rule and resize invariant. The derivative guide includes hidden-weight signs and can use the theoretical scale or a clearly labeled fitted amplitude. Float64 readout solving uses truncated SVD with optional stable ridge damping.
